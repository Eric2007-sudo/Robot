<h1 align="center">Part of A*</h1>

这份文档讲一种全局规划参考实现：在占据栅格上寻找从起点到目标的合法路径。内容包括 Dijkstra、A\*、启发函数、移动代价和对角移动约束。作业验收关注路径合法、安全和可执行，不强制唯一搜索算法或几何最短性。

读完你应该能写出 `astar_planner.cpp` 里的 `planPath`，并让它通过单元测试。

## 一、问题

给定：一张栅格地图（哪些格是障碍已知）、起点、目标。求：一条从起点到目标、不穿过障碍的合法路径。几何最短是 Dijkstra/A* 的一个优化目标，但本题允许增加安全代价或采用其他规划方法，因此不作为统一验收条件。

路径可达并不等于路径正确。本题硬性检查路径合法性；如果所选算法使用启发函数和移动代价，它们仍须与搜索模型一致。后文的最短性讨论用于理解 A*/Dijkstra 的理论性质，不是本作业的路径长度验收条件。

## 二、Dijkstra：按实际代价扩展

Dijkstra 从起点开始，按当前已知代价从小到大扩展格子。当目标被取出时，沿前驱关系回溯即可得到最短路径。

实现上用一个**优先队列**（小顶堆），每次取出"当前已知距离最小"的格子扩展：

```
把起点放进队列，起点距离 = 0
while 队列非空:
    取出距离最小的格子 cur
    如果 cur 是目标: 回溯路径，结束
    对 cur 的每个相邻格子 next:
        新距离 = cur 的距离 + 走一步的代价
        如果新距离 < next 已知的距离:
            更新 next 的距离，把 next 放进队列，记下 next 的"前驱"是 cur
```

关键在最后几行：**每个格子记住一个"前驱"（came-from）**，最后从目标一路回溯到起点，就得到路径。

Dijkstra 的问题：它向**四面八方**漫，不关心目标在哪。起点到目标明明在右边，它却把左边也漫了个遍。地图一大就慢。

## 三、A*：给 Dijkstra 一个"方向感"

A\* 就是 Dijkstra 加一个**启发函数**。启发函数 `h(格子)` 估计"从这个格子到目标还要走多远"。搜索时按 `f = g + h` 排序：

- `g`：起点到当前格子的**实际**最短代价（已经算出来的）；
- `h`：当前格子到目标的**估计**代价（启发函数）；
- `f = g + h`：经过这个格子去目标的**总代价估计**。

优先队列每次取出 `f` 最小的格子。因为 `h` 给了一个"往目标走更划算"的偏置，搜索会优先朝目标方向推进，而不是四面八方漫。

代码上，Dijkstra 和 A\* 只差一行：队列排序的 key 从 `g` 换成 `f = g + h`。

## 四、启发函数的选择

启发函数不能随便选。它的正确性由一个性质保证：

> **可采纳性（admissible）**：启发函数估计的代价，永远**不超过**真实最短代价。

在满足 A\* 的标准条件时，可采纳的 `h` 可以保证相对于所定义代价函数的最优解。这里的“最优”取决于代价定义；代价若包含安全距离惩罚，最优路线不一定是几何长度最短路线。

本题用**欧氏距离**作为启发：

```cpp
h(row, col) = hypot((col - goal_col) * res, (row - goal_row) * res)
```

两点之间直线最短，欧氏距离永远不超过真实路径长度，所以可采纳。

8 邻域下不能使用曼哈顿距离。曼哈顿距离会高估对角移动的实际代价，破坏启发函数的可采纳性，可能使 A* 返回非最短路径。

如果使用 A*，启发函数必须与邻域和移动代价匹配：8 邻域通常使用欧氏或八方向距离，避免使用会高估代价的启发函数。

## 五、走一步的代价

8 邻域意味着一个格子有 8 个邻居：

```
直方向（4 个）：上下左右，代价 = resolution（走一格）
对角方向（4 个）：四个斜角，代价 = resolution × √2（走斜边）
```

对角代价为什么是 `√2`：从格子 A 斜走到对角格子 B，几何上走的是边长 `resolution` 的正方形的对角线，长度 `resolution × √2`。

## 六、对角移动约束

8 邻域允许对角移动，但有一个问题：**穿墙角**。

看这张 2×2 的图：

```
自由    障碍
障碍    自由
```

如果从左上角斜走到右下角，两个端点可能都是自由格，但移动线段会穿过两块障碍的夹角。对于有尺寸的机器人，这条路径不满足安全约束。

所以约定：**对角移动时，两个相邻的直方向格子都必须是自由格**，否则禁止这次对角移动。更直观地说：斜着走，要求"拐角"两边都不能是障碍。

```cpp
// 从 (c, r) 斜走到 (nc, nr)，两个直邻是 (nc, r) 和 (c, nr)
if (isOccupied(nc, r) || isOccupied(c, nr)) 跳过这次对角移动;
```

单元测试 `CannotCutBlockedCorner` 和 `verify_planner` 会检查这条约束。`AvoidsObstacle` 只检查路径合法性，不检查最短性。

## 七、实现结构

```cpp
// 1. 起点、终点转成格子
worldToGrid(start) -> (sc, sr)
worldToGrid(goal)  -> (gc, gr)

// 2. 起点或终点是障碍 -> 直接返回空

// 3. 数据结构
//    open：小顶堆，元素 = (f, col, row)，按 f 排序
//    g_score：哈希表，格子的 key -> 已发现的最短 g
//    came_from：哈希表，格子 -> 前驱格子（回溯用）

// 4. 主循环
把起点 push 进 open，g_score[start] = 0
while open 非空:
    pop 出 f 最小的 cur
    if cur == 目标: 回溯 came_from，转成世界坐标路径，返回
    for 8 个方向的 next:
        跳过越界、障碍
        跳过被禁止的对角（穿墙角）
        新 g = g_score[cur] + 步长
        if 新 g < g_score[next]:
            g_score[next] = 新 g
            came_from[next] = cur
            push (新 g + h(next), next)

// 5. 队列空但没到目标 -> 不可达，返回空
```

几个实现细节：

- **格子的 key 用一维索引** `row * width + col`，比 `pair` 好写、好哈希。
- **重复扩展**：同一个格子可能被多次放进队列。弹出时如果发现它的 `g` 已经比记录的大（说明是旧的、更差的），直接跳过。
- **回溯顺序**：从目标沿 `came_from` 一路走到起点，得到的是倒序，最后 `reverse` 一下。
- **输出世界坐标**：回溯出的每个格子，用 `gridToWorld` 转成格子中心点，就是路径。

## 八、数据结构怎样对应到代码

### 8.1 一维索引

`GridMap` 已经提供了 `index(row, col)` 和 `inBounds(row, col)`。A* 可以用：

```cpp
const int id = map.index(row, col);
```

`id` 同时可以作为 `g_score`、`came_from` 和节点状态数组的索引。使用一维索引时，必须始终保持 `row * width + col`，否则障碍位置会被解释到另一列或另一行。

### 8.2 优先队列节点

开放集合中的节点至少需要保存：

```text
row, col       当前格子
g              起点到当前格子的实际代价
f              g + h
```

C++ `std::priority_queue` 默认是大顶堆。要实现小顶堆，需要提供比较器，使 `f` 较小的节点先被取出。相同 `f` 时可以用 `g` 或索引作为次级排序，次级规则不影响路径合法性。

同一个格子可能多次进入开放集合。更新更短的 `g` 时直接再次 push，不必在堆中查找并删除旧节点。弹出节点时检查：

```cpp
if (current.g > g_score[current_id]) {
    continue;
}
```

这一步是处理过期节点的关键。没有它，旧路径可能重复扩展大量格子，甚至影响运行时间。

### 8.3 前驱关系

`came_from[next_id] = current_id` 记录最短候选路径上的前一个格子。到达目标后：

```text
current = goal
while current != start:
    path.push_back(current)
    current = came_from[current]
path.push_back(start)
reverse(path.begin(), path.end())
```

回溯时得到的是目标到起点的逆序，忘记 `reverse` 会让控制器从目标方向反向跟踪。

## 九、`planPath` 的边界条件

实现主循环前先处理这些情况：

| 情况 | 返回结果 |
|---|---|
| 起点或终点在地图外 | 空路径 |
| 起点或终点是 `>= occupied_threshold` | 空路径 |
| 地图没有可用数据 | 空路径 |
| 开放集合耗尽仍未到达 | 空路径 |
| 起点和终点落在同一格 | 至少返回该格中心点 |

起点和目标首先通过 `worldToGrid` 转成格子，再通过 `gridToWorld` 得到格子中心。这样 A* 的输出和单元测试使用同一套 snap 规则，不会把连续世界坐标直接混入离散搜索。

## 十、用一个小地图手算

设分辨率为 `1`，起点为 `(0,0)`，目标为 `(2,1)`，没有障碍。允许 8 邻域时，可以选择：

```text
(0,0) -> (1,1) -> (2,1)
```

总长度为：

$$
\sqrt{2} + 1 \approx 2.414
$$

如果把对角代价错误地写成 `1`，算法会低估斜向移动的真实几何距离；如果使用 A*，启发函数必须与实际移动模型匹配，避免高估可行代价。

## 十一、常见症状与处理

| 现象 | 优先检查 |
|---|---|
| 路径整体镜像 | `row/y`、`col/x` 是否写反 |
| 起点或终点偏一格 | 是否使用 `floor`、是否先 snap 到格中心 |
| 路径比参考路径长 | 曼哈顿启发、对角代价、节点提前结束条件 |
| 路径从障碍角落穿过 | 是否检查两个直邻格 |
| 路径顺序反了 | 回溯后是否 `reverse` |
| 大地图搜索很慢 | 是否跳过过期堆节点，是否正确记录 `g_score` |

## 十三、小练习

**1.** 8 邻域、`resolution = 1`。从格 `(0,0)` 到格 `(1,1)`，走对角一步的代价是多少？如果启发函数用曼哈顿距离，`h` 是多少？这个 `h` 可采纳吗？

**2.** 4×3 地图，障碍是格 `(2,1)`，起点 `(0,1)`、目标 `(3,1)`。禁止穿墙角时，最短路径多长？（提示：`√2 ≈ 1.414`）

**3.** 一个格子的 `g_score` 已经更新过多次，堆里还留着它的旧条目。弹出旧条目时怎么判断它过期了？

<details>
<summary>答案</summary>

**1.** 对角一步代价 `√2 ≈ 1.414`。曼哈顿 `h = |1| + |1| = 2`。`2 > 1.414`，高估，不可采纳，会导致路径不是最短。

**2.** 单测 `AvoidsObstacle` 使用了同一张地图，但只检查路径合法性，不检查最短性。一条最短绕法是 `(0,1) -> (1,0) -> (2,0) -> (3,0) -> (3,1)`：第一步是合法对角移动，之后三步直线移动，总长 `√2 + 3 ≈ 4.414`。第一步的两个直邻 `(1,1)` 和 `(0,0)` 都自由；从 `(2,0)` 到 `(3,1)` 不能走对角，因为直邻 `(2,1)` 是障碍。

**3.** 弹出时比较"这个条目的 g"和"`g_score` 里记录的最新 g"，不相等说明过期，跳过。

</details>
